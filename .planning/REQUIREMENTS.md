# Requirements: Электронный дневник медресе

**Defined:** 2026-10-31  
**Core Value:** Учитель и менеджер видят реальный прогресс каждого ученика и могут вовремя вмешаться  
**Milestone:** v3.0 Касса и долги по месяцам

## v3.0 Requirements

Scope волны 1: роли кассы, оплата/долг по месяцам, убрать «Сальдо».  
(Источник: требования Камы 31.10.2026 + уточнения 31.10.2026.)

### Roles & cash desk

- [x] **CASH-01**: В системе есть роль **Кассир** (`CASHIER`) с доступом к сценариям приёма/подтверждения наличных
- [x] **CASH-02**: Кассир может **только подтверждать наличные** платежи; остальные бухгалтерские операции ему недоступны
- [x] **CASH-03**: Бухгалтер (`ACCOUNTANT`) сохраняет **полный доступ** ко всем операциям бухгалтерии (включая то, что делает кассир)

### Tuition by month

- [x] **TUITION-01**: Заявка на оплату опекуна содержит **один месяц** на всю заявку (все выбранные дети — тот же месяц)
- [x] **TUITION-02**: На экране оплаты опекун выбирает месяц в селекте/календаре, где **сразу видны неоплаченные месяцы**
- [x] **TUITION-03**: Бухгалтер видит и ведёт долг ученика/опекуна **по месяцам** (за какой месяц долг)
- [x] **TUITION-04**: Кассир видит, **за какой месяц** опекун не оплатил

### Payments UI

- [x] **PAYUI-01**: В таблице платежей учеников колонка **«Сальдо»** убрана
- [x] **PAYUI-02**: Экспорт Excel платежей **не содержит** колонку «Сальдо»
- [x] **PAYUI-03**: Статусы оплаты (Аванс / Оплачено / Долг и т.п.) продолжают отображаться без колонки сальдо

### Testing (quality gate — все волны бухгалтерии 3.x)

На **весь** функционал волн v3.0–v3.3 обязательны автотесты в том же изменении/фазе, что и фича (unit + E2E по правилам проекта). Без тестов фаза не считается done.

- [x] **TEST-01**: Для каждого REQ волны v3.0 есть покрывающие тесты (роли кассира, месяц заявки/долга, отсутствие «Сальдо» в UI и Excel) — *Phase 16: роли кассира ✓; Phase 17: месяц заявки/долга ✓; Phase 18: Saldo UI+Excel ✓*
- [ ] **TEST-02** *(v3.1, критично)*: Unit-тесты **калькуляции ЗП** покрывают все компоненты формулы (часы×ставка×коэф., пунктуальность работы/урока, аттестация×1000, выходные 600+50×N, граничные N=0/1/N)
- [ ] **TEST-03** *(v3.1, критично)*: Тесты **выдачи ЗП** (accrual → confirm → payout до 10-го; отказ/границы ролей бухгалтера)
- [x] **TEST-04**: Регрессия: существующие tuition/salary brownfield-сценарии не ломаются после изменений волны — *Phase 16: cashier/accountant matrix ✓; Phase 17: create/confirm+month + cashier-role ✓; Phase 18: cashier-role + payments-saldo ✓*

## Future Requirements

Отложено на следующие волны (не в roadmap v3.0).

### v3.1 — ЗП 3.0, явка, окна

Числа ниже — **дефолты** при запуске; все должны меняться из UI (см. SAL-CFG).

- **SAL-01**: ЗП = часы × ставка × мужской коэффициент (дефолт выдаётся, меняет менеджер)
- **SAL-02**: За месяц начисления: если опозданий на работу &lt; 3 → надбавка +1000 ₽
- **SAL-03**: Опоздание на урок: минуты = факт старта − начало окна; −10 ₽ / мин
- **SAL-04**: Аттестация (= квалификация = ПК): 1000 ₽ × N; действует полгода; начисляется каждый месяц периода
- **SAL-05**: Надбавка за выходной день (учителя не работают): только при N≥1; 600 + 50×N ₽/день (мин. 650 при N=1)
- **SAL-06**: Выдача ЗП до 10-го числа
- **SAL-CFG-01**: Все параметры формулы ЗП и надбавок **настраиваются из UI** (не хардкод): мужской коэффициент (дефолт и per-teacher), порог опозданий на работу и сумма надбавки, штраф ₽/мин за опоздание на урок, сумма за 1 аттестацию, срок действия аттестации (мес.), база выходного дня и +₽ за каждую аттестацию, дедлайн выдачи ЗП (число месяца). Меняет менеджер (и при необходимости бухгалтер с полным доступом)
- **SAL-CFG-02**: Изменение параметров применяется к новым начислениям; история/уже подтверждённые accrual не пересчитываются молча (явные правила в plan-phase)
- **ATTEND-01**: Кнопки «Я пришёл» / «Завершить рабочий день»; уроки и оценки только в этом интервале
- **WINDOW-01**: Система окон учителей с редактированием (источник старта урока для SAL-03)
- **TEST-02 / TEST-03**: обязательны в scope v3.1 (калькуляция и выдача ЗП — приоритетное покрытие); тесты читают конфиг/подставляют параметры, а не зашитые константы
