# Уважительные пропуски и причина — дизайн

Дата: 2026-07-30  
Статус: утверждено в обсуждении

## Цель

Учитель при отметке «Прогул» может указать, что пропуск уважительный, и при желании ввести текст причины. В аналитике «Требуют внимания» пропуски показываются раздельно (неуважительные / уважительные). Сигнал риска по пропускам учитывает только неуважительные.

## Решения

| Тема | Решение |
|------|---------|
| Модель данных | Поля на `Session`: `absenceExcused`, `absenceReason` |
| Текст причины | Всегда необязателен |
| Риск / колонка «Пропуски» (логика) | Только `ABSENT` и `absenceExcused === false` |
| Отображение в аналитике | Одна колонка «Пропуски», два бейджа: красный (неуваж.), жёлтый (уваж.) |
| Часы по уважительной | Не считаем — только количество пропусков |

## Данные

### Prisma (`Session`)

```prisma
absenceExcused Boolean @default(false)
absenceReason  String?
```

Миграция: только `ADD COLUMN` с default `false` / nullable. Существующие прогулы = неуважительные.

### Правила записи

- Поля значимы только при `attendance === ABSENT`.
- При сохранении с `PRESENT` или `LATE`: `absenceExcused = false`, `absenceReason = null`.
- При `ABSENT`: сохранять переданные `absenceExcused` и `absenceReason` (пустая строка → `null`).
- Валидация Zod: оба поля опциональны; при не-ABSENT сервер принудительно сбрасывает.

## Журнал (страница урока)

### UI

В `AttendanceButtons` (или рядом) при `value === 'ABSENT'`:

1. Чекбокс / Switch «Уважительная причина» (default off).
2. Input/TextArea «Причина» (placeholder вроде «Болезнь, семейные обстоятельства…»), необязательно.

При «Пришёл» / «Опоздал» блок скрыт.

### Состояние и сохранение

- Локальный state в `use-lesson-page` (рядом с `attendance` / `lateMinutes`).
- При загрузке существующей сессии — подтянуть `absenceExcused` / `absenceReason`.
- POST `/api/sessions` и связанные типы/валидации — передать поля.
- `Session.note` не использовать для причины пропуска.

## Аналитика

### Подсчёт

В `attendance-risk` / метриках at-risk:

- `absencesInMonth` (неуважительные) = `ABSENT && !absenceExcused && !isAdjustment` в месяце.
- `excusedAbsencesInMonth` = `ABSENT && absenceExcused && !isAdjustment` в месяце.
- Порог риска и streak подряд — только по неуважительным.

### UI (`AtRiskStudentsTable`)

Колонка «Пропуски»: в ячейке бейджи (Ant Design `Tag` или аналог существующих risk-бейджей):

- красный — число неуважительных (если > 0);
- жёлтый — число уважительных (если > 0);
- если оба 0 — «0» или «—» (как принято в соседних колонках пустых значений).

Часы / «Время» / «Норматив» не меняются.

### Прочие места

MVP: бейджи только в «Требуют внимания».  
`LevelStats` / `TopStudents` («Прогулы»): в число входят только неуважительные; бейджи не добавляем.

## Поток данных

```
Учитель → AttendanceButtons (ABSENT + excused + reason)
  → use-lesson-page → POST /api/sessions
  → Session.absenceExcused / absenceReason
  → evaluateAttendanceRisk / at-risk query
  → AtRiskStudentsTable (бейджи)
```

## Тестирование

- Unit: валидация session schema; `countStudentAbsencesInMonth` / risk — excused не входит в порог; excused считается отдельно.
- E2E (по правилу new-module-tests): отметить прогул с уважительной причиной → сохранить → в аналитике жёлтый бейдж; неуважительный → красный и риск при пороге.

## Вне скоупа

- Часы/минуты пропущенного урока по уважительной причине.
- Отдельный справочник причин.
- Изменение label кнопки «Прогул» на «Отсутствовал».
- Обязательность текста причины.
