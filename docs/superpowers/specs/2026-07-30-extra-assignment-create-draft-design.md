# Черновик создания доп. задания — дизайн

Дата: 2026-07-30  
Статус: утверждено в обсуждении

## Цель

При создании доп. задания введённые данные не теряются из‑за случайного клика снаружи, Escape/крестика или перезагрузки/выключения устройства. При повторном открытии «Создать задание» форма восстанавливается из локального черновика. Клик по затемнению вокруг модалки окно не закрывает.

## Решения

| Тема | Решение |
|------|---------|
| Хранение | `localStorage` на клиенте |
| Область | Только режим **создания** (не редактирование) |
| Очистка черновика | Успешное сохранение и кнопка «Отмена» |
| Мягкое закрытие | Крестик и Escape — закрывают окно, черновик оставляют |
| Клик снаружи | `maskClosable={false}` — не закрывает |
| Серверный черновик | Не делаем |
| Индикатор «есть черновик» в UI | Не делаем (можно позже) |
| Модалка «Дать доп. задание» в журнале | Без изменений |

## Поведение

1. Пользователь открывает «Создать задание» на странице каталога доп. заданий.
2. Если в `localStorage` есть валидный черновик для текущих `userId` + `subjectId` — поля формы заполняются из него.
3. При изменении названия, уровня, шага или содержания — debounce-запись черновика (~300 ms).
4. Клик по затемнению ничего не делает (окно остаётся открытым).
5. Крестик / Escape — закрывают модалку; черновик сохраняется.
6. «Отмена» — очищает черновик и закрывает модалку.
7. Успешное «Сохранить» — очищает черновик и закрывает модалку (как сейчас после create).
8. Редактирование существующего задания: без черновика; данные с сервера; `maskClosable={false}` тоже применяем для единообразия.

## Данные черновика

Ключ:

```text
extra-assignment-draft:{userId}:{subjectId}
```

Значение (JSON):

```ts
type ExtraAssignmentCreateDraft = {
  title: string
  levelId?: string
  stepId: string | null
  content: StepContent // как в createExtraAssignmentSchema / StepEditor
}
```

## Код

### Новый модуль

`src/features/extra-assignments/lib/extra-assignment-draft.ts`

По аналогии с `journal-storage.ts` / `analytics-storage.ts`:

- `readExtraAssignmentDraft(userId, subjectId): ExtraAssignmentCreateDraft | null`
- `writeExtraAssignmentDraft(userId, subjectId, draft): void`
- `clearExtraAssignmentDraft(userId, subjectId): void`
- SSR-safe (`typeof window === 'undefined'` → no-op / null)
- try/catch на доступ к `localStorage`
- битый / невалидный JSON → `null` (игнорировать)

### `ExtraAssignmentFormModal`

Новые props (или эквивалент): `subjectId`, `currentUserId` (уже есть), различение create vs edit через `assignment === null`.

- При `open && !assignment`: hydrate из draft (если есть), иначе пустая форма.
- При изменении полей в create: debounce → `writeExtraAssignmentDraft`.
- Footer «Отмена»: `clearExtraAssignmentDraft` + `onCancel`.
- `onCancel` от Modal (крестик / Escape): только закрыть, без clear.
- `maskClosable={false}`.
- StepEditor: при restore из draft передавать `initialContent` из draft и стабильный `key` (например `new-draft` / hash), чтобы редактор подхватил содержимое. Сейчас `key={assignment?.id ?? 'new'}` и `initialContent={assignment?.content}` — для create с черновиком нужно `initialContent` из draft.

### `ExtraAssignmentCatalogPage`

- Передать `subjectId={selectedSubjectId}` в модалку.
- После успешного create — `clearExtraAssignmentDraft` (если clear не сделан внутри модалки в `onSave` path; достаточно одного места — предпочтительно в модалке при успешном save callback после `await onSave`, либо в `handleSave` каталога).

## Краевые случаи

| Случай | Поведение |
|--------|-----------|
| Смена предмета | Другой ключ storage — свой черновик или пустая форма |
| Нет `userId` / отказ `localStorage` | Форма без черновика, без ошибки пользователю |
| Битый JSON | Игнор, пустая форма |
| Редактирование | Черновик create не трогаем и не читаем |
| Пустой черновик (всё по умолчанию) | Можно не писать или писать — на UX не влияет |

## Проверка (ручная)

1. Создать → набрать название и текст → клик снаружи → окно не закрылось.
2. Escape → окно закрылось → снова «Создать» → данные на месте.
3. «Отмена» → снова «Создать» → форма пустая.
4. Набрать → «Сохранить» → снова «Создать» → форма пустая.
5. Набрать → F5 / перезагрузка → «Создать» → данные на месте.
6. Редактирование существующего — без сюрпризов с чужим create-черновиком.

## Вне скоупа

- Черновик назначения из журнала («Дать доп. задание»).
- Синхронизация черновика между устройствами.
- UI-бейдж «есть несохранённый черновик».
- Автотесты Playwright на localStorage (опционально позже).
